# Sources & provenance

Every third-party skill in this pack is a **verbatim copy** of an upstream directory,
pinned to a commit. Nothing is hand-edited after vendoring — the next
`./sync-upstream.sh` overwrites it. Local behavior lives in the native skills
(`web-release-gate`, `core-web-vitals`, `visual-proof`) and in `hooks/`.

All upstreams are MIT-licensed. Each vendored skill directory carries the
upstream `LICENSE` as `UPSTREAM-LICENSE`. Where an upstream ships no LICENSE
file and declares its licence only in its README (`vercel-labs/agent-skills`
does), `UPSTREAM-LICENSE` records that declaration verbatim with the commit it
was read from. Where an upstream ships `NOTICE` files on the path from the
skill to the repository root, every one is carried as `UPSTREAM-NOTICE`, a
single file as is and several concatenated under lines naming their paths:
Apache-2.0 section 4(d) requires that attribution to travel with a
redistribution, the obligations add up, and it is carried for every licence.
None of the current upstreams ships one.

`sync-upstream.sh` applies ABSORPTION.md gate 1 before it touches `skills/`:
the licence declared in the table below must be on the allowlist, and the
upstream's licence inputs must agree with it. Every licence-looking file and
every README section headed exactly "License" (README in any case, CRLF or
LF, heading in ATX form with one to six hashes or Setext form, heading and
underline each indented at most three spaces, fenced code and every form of
HTML block ignored, a fence opening or closing at most three spaces in and
closing only on its own delimiter) between the skill and the repo root, and
every one nested anywhere inside the skill, a nested `UPSTREAM-LICENSE`
included, is read; so is the `license:` field, key bare or quoted, of every
SKILL.md frontmatter in the skill (delimiters read past a byte-order mark and
trailing blanks), and the `license` or legacy `licenses` field of every
`package.json` in the skill, a manifest that is not JSON being refused. The
text is read with its whitespace folded, so a phrase wrapped across lines is
still the phrase. The
nearest licence file on the path to the
root is recorded, else the nearest README declaration. A recognised licence
text is identified by its grant clause and checked against the exact declared
variant, so BSD-4's advertising clause fails a BSD-3 declaration, 0BSD's grant
without ISC's retention condition fails an ISC declaration, and "unlicensed"
is not the Unlicense.
Anything without a grant clause is a bare declaration and may say nothing but
the licence: all-rights-reserved, negations, qualifiers and compound
expressions (`MIT AND Apache-2.0`, `MIT OR X`, `X WITH Y`, `MIT/Apache-2.0`)
are refused; a full text is refused too when such an expression joins two
licence names above its grant. Refused as well are
copyleft and `-NC` texts, symlinked inputs, and an upstream that ships
`UPSTREAM-LICENSE`, in any case, at the skill root. A source path that is or
crosses a symlink, a skill tree containing one, and a source that is a
submodule gitlink are refused: the copy would follow or carry a pointer off
the clone, or vendor an empty directory. Before any clone, every table row is checked
for shape: a destination that names a native skill, or one listed twice (both
compared with case folded), and a source at the repository root or under
`.git`, in any case, are refused; so is a source directory with no `SKILL.md`
at its root, since replacing a skill with a directory no harness loads is not
a sync. One failing
entry aborts the whole run with the vendored tree unchanged.

The gate is pattern matching, not licence identification. It catches the
mistakes an honest pin can make and the known riders bolted onto permissive
texts, prohibitions and mandated purposes alike; it does not prove a file is
byte-for-byte the SPDX text. The vendored
diff is reviewed by a person before it merges, and that review is the
control for an upstream that sets out to deceive the patterns. Exact SPDX
text matching (`licensee`, `askalono` or similar) is a separate tool to add
in CI if that control is ever not enough. `--check` excludes `UPSTREAM-LICENSE` from the
tree comparison, because upstream does not have it, and then checks it on its
own: missing, or saying something other than what the upstream says today, is
drift. The record's `Commit:` line moves with upstream HEAD and is not drift,
but it must be present and name a commit. `UPSTREAM-NOTICE` is checked the same
way: it must match the upstream's NOTICE byte for byte, and must be absent when
the upstream has none. A vendored tree that is a symlink, or contains one, is
drift whatever it points at.

## Why these, and what each is actually good for

Assessed against what the FrankX repos already had. Verdict column is the
decision this pack encodes.

| Upstream skill | What it really is | Verdict |
|---|---|---|
| **web-design-guidelines** (Vercel) | A 46-line wrapper that `WebFetch`es the live rule list from `vercel-labs/web-interface-guidelines` and greps your files against it, output in `file:line` form. The rules never go stale because they are not stored here. | **Adopt as the audit gate.** The single highest-value skill in the set. It is the only one that produces a pass/fail on real files. |
| **review-animations / improve-animations / find-animation-opportunities** (Emil Kowalski) | Three narrow, non-overlapping motion skills: review a diff, plan a codebase-wide audit, find where motion is missing. Two of them set `disable-model-invocation: true` so they only run when asked. | **Adopt all three.** They are better factored than any single "motion" skill — one job each, and they say what *not* to animate. |
| **emil-design-eng / apple-design** (Emil Kowalski) | Craft philosophy: the invisible details, spring physics, interruptible gestures, optical typography. | **Adopt.** This is the taste layer the FrankX repos had as prose in `taste.md` but never as an activatable skill. |
| **animation-vocabulary** (Emil Kowalski) | Reverse dictionary: "the bouncy thing when a popover opens" → *Pop in*. | **Adopt.** Cheap, and it makes motion briefs precise instead of vague. |
| **ui-ux-pro-max** (nextlevelbuilder) | A searchable CSV database — 84 styles, 192 palettes, 74 font pairings, 98 UX guidelines, 22 stacks — plus a Python query script. | **Adopt, and it is an upgrade.** The copy already sitting in `FrankX/.claude/skills` and `frankx.ai-vercel-website/.claude/skills` is an older, smaller fork (50 styles / 21 palettes / 8 stacks, no GSAP presets, no `references/`). The install script replaces it. |
| **extract-design-system** (arvindrk) | Thin wrapper over `npx extract-design-system` + Playwright: scrapes computed styles from a public URL, emits W3C `tokens.json` + `tokens.css`. Has genuinely good safety boundaries ("do not treat a single page as proof of a whole design system"). | **Adopt for competitive/reference work only.** Never point it at frankx.ai and re-import the result — the tokens of record are `tailwind.config.js` + `design.md`. |
| **image-to-code** (Leonxlnx) | Generate a reference image per section first, analyze it, then implement. Long (1200+ lines), written against Codex, image-generation dependent. | **Adopt with a caveat.** Real value: it forbids the "one giant compressed mockup for eight sections" failure. It expects an image-gen tool to be available; on Claude Code that means the repo's own gen lane (`scripts/nb-generate.mjs`, Higgsfield MCP), not a built-in. |
| **brandkit** (Leonxlnx) | Brand-identity boards: logo systems, palettes, mockups, 3×3 presentation grids. | **Adopt, scoped.** It is for *new* sub-brands and products. Pointing it at frankx.ai would fight `frankx-brand` / `brand-guidelines` / `design.md`, which are already locked. `web-release-gate` states this boundary. |
| ~~pick-ui-library~~ (Emil Kowalski) | Curated library picks per task. | **Skipped.** Useful, but it is a shopping list, not a quality gate, and the FrankX stacks are already chosen (Framer Motion + GSAP + Lenis + Tailwind + shadcn). Add it later if the stack opens up. |
| ~~taste-skill / minimalist / brutalist / soft~~ (Leonxlnx) | Whole-aesthetic instruction sets that impose their own look. | **Skipped deliberately.** The FrankX properties have a locked aesthetic in `design.md` + `taste.md`. Importing a competing style skill is how a site drifts. |

## What none of them do — hence the three native skills

The upstream set is strong on *judgment* and weak on *proof*. Nothing in it:

- sequences the others, or refuses to let work be called done (`web-release-gate`)
- measures anything — no Core Web Vitals, no bundle budget, no Lighthouse (`core-web-vitals`)
- produces before/after visual evidence at real breakpoints in both themes (`visual-proof`)
- knows your tokens exist (all three native skills read `design.md` / `taste.md` / `tailwind.config.js` when present)

## Known risk: `web-design-guidelines` fetches live, unpinned rules

The thing that makes this skill good is also its weak point. Ten of the eleven
vendored skills are frozen at a commit; this one deliberately is not. Every run
does a `WebFetch` of

```
https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md
```

— the mutable `main` branch — and the skill tells the agent that the fetched
content *is* the rule set to apply. So a compromise or a bad edit upstream
reaches every session that runs it, with nothing pinned and nothing diffed
against a known-good copy. That is a prompt-injection and supply-chain surface,
not a hypothetical one.

Kept as-is for now, deliberately: pinning it would forfeit the freshness that
makes it worth having over a static checklist, and the upstream is Vercel's own
repo. But it is the one place in this pack where trust is delegated at run time
rather than at vendor time, and it should be a conscious choice rather than an
accident.

If that trade stops being acceptable, the options in order of preference:

1. Pin the fetch to a commit SHA in the skill body and bump it on a schedule —
   keeps the audit deterministic, costs a periodic manual bump.
2. Vendor `command.md` alongside the skill and diff the live copy against it,
   surfacing changes instead of applying them silently.
3. Treat the fetched file as reference *data* to check code against, never as
   instructions to follow — the narrower framing, and the one that removes the
   injection vector rather than just narrowing it.

Note that `sync-upstream.sh` will overwrite any hand-edit to this skill. Change
it in the `UPSTREAM[]` table or in a wrapper, not in the vendored file.

## Known upstream defects (vendored, not patched here)

A vendored skill is never hand-edited: the next `./sync-upstream.sh` would
overwrite the fix. These were found in review and checked against the
upstream HEAD at the time, so they belong upstream. Until then, the native
`web-release-gate` tells the agent how to work around the ones that change an
outcome.

| Skill | Defect | Effect | Handled by |
|---|---|---|---|
| `ui-ux-pro-max` | SKILL.md runs `search.py` under `${CLAUDE_PLUGIN_ROOT}` | Unset for a project skill, so the documented command fails | `web-release-gate` gives the repo-relative command |
| `ui-ux-pro-max` | `design_system.py` emits `transition: all` in button and card templates | A generated MASTER.md breaks the gate's own baseline | `web-release-gate` marks generated output as a draft below the gate |
| `ui-ux-pro-max` | Primary-button text is hard-coded `white`, ignoring the palette's On Accent | White-on-white CTAs for light-accent palettes | `web-release-gate` says to check that contrast |
| `ui-ux-pro-max` | MASTER.md points to `design-system/pages/`; overrides are written to `design-system/<project>/pages/` | An agent following the master misses its page overrides | `web-release-gate` names the real path |
| `ui-ux-pro-max` | `--persist --page` returns early once MASTER.md exists | The page override is never written without `--force`, which also overwrites the master | Upstream only |
| `ui-ux-pro-max` | Synonym normalization uses `str.replace`, so `navigation` becomes `navigationigation` | `nav` and `navigation` queries return different results | Upstream only |
| `extract-design-system` | Runs `npx extract-design-system` and `npx playwright install` unpinned | Fetches whatever the registry serves, outside the lockfile | Use only for reference URLs, as above; skip where the repo's contract forbids unlisted tooling |

## Re-syncing

```bash
cd packs/web-excellence
./sync-upstream.sh --check   # drift report, changes nothing
./sync-upstream.sh           # re-vendor + rewrite the pin table above
```

Run `--check` before trusting a vendored skill you have not synced in a while;
upstream motion and guideline skills move fast.
