## What the numbers do and do not say

- Outcome n is 4 runs per arm per skill (2 cases times 2 runs). That is too small to call a delta of 0.25 anything but noise. Treat every delta here as a probe, not a benchmark.
- Zero skills pass the rule. The bundle list limited to passing skills is empty [MEASURED].
- Four of the failures come from my own case design and the harness, not from the skills:
  - The eval sandbox working directory is empty. feynman-thinking and loop-designer prompts refer to "our auth middleware", "40 pages", "our CI". In every run, with and without the skill, the model answered that the directory is empty and asked where the code is. Scores of 0.00 and 0.00 mean the cases are invalid, not that the skills do nothing. Fix: make each prompt self-contained (paste the code or a spec into the prompt).
  - hooks-automation outcome-a: both arms asked clarifying questions about the formatter, so the judge failed all four runs.
  - Seven runs ended in a harness error: 4 timeouts at 300 s (ai-architect-review outcome-a once per arm, langgraph-patterns outcome-a twice with the skill) and 3 turn-limit stops (hooks-automation outcome-b both arms, loop-designer outcome-b with the skill). Errored runs score 0 and are included in the means.
  - One mcp-architecture baseline run had its judge skipped by the cost ceiling. It is excluded from the means, so that row has n of 4 versus 3.
- Real signals worth acting on:
  - hooks-automation never fired in 4 with-skill runs (Fired 0.00) [MEASURED]. Its description mentions Claude Code hooks, but the body is built around the `claude-flow` CLI. It also cost 5.26 USD, the most of any skill, because runs hit the turn limit.
  - agentic-orchestration and mcp-architecture fired every time and the baseline already scored 1.00 or 0.75 on the same rubric. On these cases the skill adds no measurable lift; the model already knows the material.
  - No-trigger false positives: 0 of 2 for every skill that ran [MEASURED].
  - The with-skill arm was cheaper per run than the baseline on some cases (agentic-orchestration outcome-b: about 0.11 against 0.31 to 0.39 USD per run) because the baseline used more turns. One case, not a result.

## What this run cannot independently grade

- Skill authorship. The ten skills carry authors "Frank Riemer", "Claude Flow Team" and unattributed Claude sessions. I wrote none of them. I wrote the cases and graders. Independence of the cases from the skill text is partial: I read each skill before writing its cases, so some graders echo skill vocabulary (for example the MADE, DEFERRED, UNMADE tokens in ai-architect-review, the model IDs in model-routing).
- Same-provider judging. The model under test is Anthropic and the judge is Anthropic (Haiku). Several skills were also drafted with Claude. The second-provider pass the product plan requires has not happened [OPEN].
- Skill isolation. Whether user-level skills leak into the baseline arm comes from the CLI documentation as summarised by a docs agent, not from a check I ran. The baseline arm has no skill-fired grader, so I did not check it for stray Skill calls.
- Substitution. Five of the ten candidates named in `products/skills-with-evals-pack.md` (fail-closed-eval-gate, tool-allowlist, run-receipt, agent-stop-conditions, mcp-least-privilege) do not exist in claude-skills-library or claude-code-config on 2026-10-06. claude-md exists in claude-code-config but sets `disable-model-invocation`, so a trigger eval cannot fire it. agent-design-review exists only on the unmerged PR 43 branch. I replaced them with ai-architect-review, loop-designer, todo-discipline, verification-quality, langgraph-patterns, hooks-automation and feynman-thinking.
